# Sinced - 데이터 모델

## 엔티티 구조

```
Category (1) ─────< (N) Item (1) ─────< (N) LogEntry
```

- 카테고리는 여러 항목을 가짐
- 항목은 여러 행위 기록(LogEntry)을 가짐
- 항목 삭제 시 관련 LogEntry는 함께 삭제(Cascade)
- 카테고리 삭제 시 항목의 categoryId는 null로 설정 (SET NULL)

## Room 엔티티

### Category
```kotlin
@Entity(tableName = "categories")
data class Category(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val name: String,
    val color: Int? = null,        // ARGB, 카테고리 시각 구분 (옵션)
    val sortOrder: Int = 0,        // 사용자 직접 정렬용
    val createdAt: Long            // epoch millis
)
```

### Item
```kotlin
@Entity(
    tableName = "items",
    foreignKeys = [ForeignKey(
        entity = Category::class,
        parentColumns = ["id"],
        childColumns = ["categoryId"],
        onDelete = ForeignKey.SET_NULL
    )],
    indices = [Index("categoryId"), Index("archivedAt")]
)
data class Item(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val name: String,                       // 예: "샤워기 필터"
    val categoryId: Long? = null,
    val cycleDays: Int? = null,             // null이면 경과일만 추적, 값 있으면 D-day 계산
    val memo: String? = null,
    val sortOrder: Int = 0,                 // 사용자 직접 정렬용
    val createdAt: Long,
    val archivedAt: Long? = null            // 보관(숨김) 처리용. 삭제 대신 사용
)
```

### LogEntry
```kotlin
@Entity(
    tableName = "log_entries",
    foreignKeys = [ForeignKey(
        entity = Item::class,
        parentColumns = ["id"],
        childColumns = ["itemId"],
        onDelete = ForeignKey.CASCADE
    )],
    indices = [Index("itemId"), Index("performedAt")]
)
data class LogEntry(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val itemId: Long,
    val performedAt: Long,                  // 행위가 일어난 시각 (소급 입력 가능)
    val note: String? = null,
    val createdAt: Long                     // 기록을 등록한 시각 (감사용, performedAt과 다를 수 있음)
)
```

## 파생 값 (DB에 저장하지 않고 계산)

리스트 표시용으로 항목마다 다음 값을 계산:

| 값 | 계산 방식 |
|----|----------|
| `lastPerformedAt` | 해당 itemId의 LogEntry 중 `MAX(performedAt)` |
| `daysSince` | `today - lastPerformedAt` (일 단위, 내림) |
| `nextDueAt` | `cycleDays != null` 일 때 `lastPerformedAt + cycleDays * 1day` |
| `daysUntilDue` | `nextDueAt - today` (일 단위). UI 표기는 양수 → `D-N`, 0 → `D-DAY`, 음수 → `D+\|N\|`. 자세한 표기 규칙은 `03_화면_설계.md` 상단 참조 |
| `status` | 아래 표 참조 |

### status 분류

**평가 순서: 위에서 아래로, 첫 번째 매치된 상태 채택.** 즉 LogEntry가 0건이면 `cycleDays` 유무와 무관하게 `NEVER_LOGGED`.

| 순위 | 조건 | status |
|------|------|--------|
| 1 | 기록 없음 (LogEntry 0건) | `NEVER_LOGGED` |
| 2 | `cycleDays == null` | `TRACKING_ONLY` (경과일만 표시) |
| 3 | `daysUntilDue < 0` | `OVERDUE` (빨강) |
| 4 | `daysUntilDue == 0` | `DUE_TODAY` (주황) |
| 5 | `daysUntilDue <= 3` | `DUE_SOON` (노랑) |
| 6 | 그 외 | `OK` |

## DAO 핵심 쿼리 (개념)

```kotlin
// 리스트 화면용: 항목 + 마지막 기록 시각을 한 번에 가져오는 뷰
@Query("""
    SELECT i.*, MAX(l.performedAt) AS lastPerformedAt
    FROM items i
    LEFT JOIN log_entries l ON l.itemId = i.id
    WHERE i.archivedAt IS NULL
    GROUP BY i.id
""")
fun observeItemsWithLastLog(): Flow<List<ItemWithLastLog>>
```

- 정렬/필터링은 가져온 후 ViewModel에서 처리 (항목 수가 많지 않다는 가정)
- 항목 수 많아지면 SQL ORDER BY로 이전

## 초기 시드 데이터
첫 실행 시 기본 카테고리 4종 생성 (색상은 다크 테마 가독성 기준 프리셋에서 자동 배정):

| name | 색상 의도 |
|------|----------|
| 청소 | 청록 (Cyan 계열) |
| 구독 | 보라 (Purple 계열) |
| 교체/소모품 | 황토 (Amber 계열) |
| 건강 | 초록 (Green 계열) |

> 정확한 ARGB 값은 `ui/theme/Color.kt`에서 darkColorScheme과 함께 결정.
> 사용자는 자유롭게 이름·색상·순서 수정 / 삭제 가능. 카테고리 색상 팔레트는 6~8색 프리셋 제공(컬러피커는 후순위).

## 마이그레이션 정책
- 1차 버전은 schema version 1
- 이후 변경 시 Room `Migration` 객체 추가, `fallbackToDestructiveMigration()` 사용 금지 (이력 보존이 핵심이므로)
